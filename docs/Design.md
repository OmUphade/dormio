# Design System & UI Process — Dormio

> ## 🔒 STRICT RULE: ALL UI DECISIONS COME FROM **UI UX PRO MAX**. AGENTS HAVE NO DESIGN OPINIONS.
> Antigravity (or any agent) must **not** use its own taste for any part of the UI. Layout, composition, colors, typography, spacing, radius, elevation, icons, illustrations, charts, motion, form patterns, navigation, empty/error states, responsive behavior: **every decision must trace back to output of the UI UX Pro Max skill** (`.agents/skills/ui-ux-pro-max/`).
> If a decision is missing, the agent runs a **gap query** with the skill and records the answer. It never decides by itself. If the skill is unavailable, the agent **stops and tells the owner**.
>
> **Allowed sources of UI truth (in order):**
> 1. `design-system/dormio/pages/<page>.md` (page spec built from skill output)
> 2. `design-system/dormio/MASTER.md` (system generated by the skill)
> 3. This file's **Bans** (§3) — restrictions only; they add no design.
>
> This file contains no palette, fonts, or layouts on purpose. Those come from the skill.

## 1. Design Brief (input to the skill; not a design)

**Product:** Dormio — a marketplace to find hostels, PGs and messes by area, plus a living and operating system for residents, owners and institutions.

**Audience and feeling**
| Audience | Feeling to achieve |
|---|---|
| Seekers (students, working professionals, parents) | Exciting, clear, trustworthy, image-led |
| Residents / subscribers | Calm, helpful, everyday-friendly |
| Owners | Professional, in control, simple, guided, big touch targets |
| Guards | Instant clarity at a glance |
| Institution and platform admins | Efficient, data-first, readable |

**Brand personality (use as query keywords):** warm, youthful, trustworthy, local, friendly, India.
**Product keywords:** marketplace, accommodation, student housing, hostel, PG, food, mess, local discovery, map search, listing, rating, booking, rent, dashboard, mobile-first, PWA.
**Owner's stated dislikes:** black or dark pages, gradients, plain white pages with text in boxes, every page looking the same.
**Owner's stated wants:** a rich, colorful-but-tasteful, image-led, well-aligned UI with visual variety between pages.

**Stack the skill must target:** Next.js (React, App Router) + Tailwind + shadcn/ui → always pass `--stack nextjs` and `--stack shadcn` where relevant.

## 2. The UI Gate (mandatory for EVERY UI task)

Evidence for each step must appear in the page spec and in the agent's final message.

**Step 0 — Skill check.** `ls .agents/skills/ui-ux-pro-max/scripts/` and `python3 .agents/skills/ui-ux-pro-max/scripts/search.py --help` (lists available domains). If missing → STOP, tell the owner.

**Step 1 — Master exists?** `design-system/dormio/MASTER.md`. If not, generate it (§2.1) before anything else.

**Step 2 — Research with the skill for this page/component** using the Query Playbook (§4). Always run at least: the page-level design-system command, one `--domain ux`, one `--domain style`, one `--stack nextjs`. Add `--domain icons` for icon choices and `--domain chart` for any chart. Use `--json` if output is truncated.

**Step 3 — Write the Page Spec** `design-system/dormio/pages/<name>.md` (template in §5). Decisions in it must be copied or derived from skill output, with the query that produced each. Include layout sketches for 360 / 768 / 1280 px, states, real copy, imagery needs.

**Step 4 — Build** using only tokens/components from MASTER.md and the spec. Start each `page.jsx`/`layout.jsx` with `// ui-spec: design-system/dormio/pages/<name>.md`. New shared components get a row in `design-system/dormio/COMPONENTS.md`.

**Step 5 — Verify visually.** Run the app; take Playwright screenshots at 360, 768, 1280 px into `design-system/dormio/screenshots/<name>/`; OPEN them; review against §8; fix and re-shoot (max 3 rounds). If a fix needs a design decision, run a gap query.

**Step 6 — Automated gates.** `bash scripts/check-ui-rules.sh`, `bash scripts/check-ui-provenance.sh`, axe. All must pass.

**Step 7 — Index.** Add the page to `design-system/dormio/PAGES.md`.

## 3. Bans (restrictions only; checked by review and scripts)

1. **No gradients** (`linear/radial/conic-gradient`, Tailwind `bg-gradient-*`, `from-*`/`via-*`/`to-*`). Flat fills only.
2. **No black** (`#000`, `black`, `bg-black`, `text-black`, near-black surfaces). **No dark theme in v1.** Text uses the darkest non-black token the skill chose.
3. **No plain "white page with identical bordered boxes".** Pages need purposeful color areas, imagery, and hierarchy as chosen via the skill.
4. **At most one grid of identical cards per page.**
5. **No consecutive pages with the same composition.** Neighbouring pages in a flow must use different layout structures.
6. No glassmorphism/blur, neon glow, "AI purple/pink" aesthetics, emoji as icons, icon-in-circle feature rows.
7. No default shadcn look: all tokens from MASTER.md.
8. No lorem ipsum or gray placeholder boxes.
9. No hard-coded hex colors or Tailwind arbitrary values for color/spacing/radius/font-size; tokens only (`tokens.css`).
10. No body text under 14 px, no touch target under 44 px, no horizontal scroll at 360 px.

## 8. UI Review Checklist (QA, not design; agent ticks before finishing)

- [ ] Page spec has a complete **UI UX Pro Max evidence** section with real commands and chosen results
- [ ] `page.jsx`/`layout.jsx` carry the `// ui-spec:` header; components registered in COMPONENTS.md
- [ ] Screenshots at 360/768/1280 reviewed; no overflow, clipping, or misaligned edges; baselines and gutters consistent with MASTER spacing
- [ ] One clear primary action; clear hierarchy
- [ ] Only token colors/spacing/fonts; no gradients; no black
- [ ] Not a flat white canvas of identical boxes; differs from neighbouring page
- [ ] Real copy and imagery; all states built
- [ ] Contrast ≥ 4.5:1, focus visible, targets ≥ 44 px, labels, alt text
- [ ] `check-ui-rules.sh`, `check-ui-provenance.sh`, axe pass; PAGES.md updated

## 9. Content Tone
Plain, kind, specific; errors say what happened and what to do next. Seeker copy is concrete ("3 beds left · ready from 1 Nov"); owner copy is step-by-step; emergency copy puts the action first. Dates `12 Oct 2026`, times `9:30 PM`; INR `₹12,500`. English only (strings externalized). Any visual treatment of this copy comes from the skill.

## 10. Accessibility and Motion
WCAG 2.1 AA, keyboard operable, reduced-motion respected. Motion style and timing come from the skill's UX guidance; emergency alerts never animate.
