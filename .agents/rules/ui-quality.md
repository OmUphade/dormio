# Dormio UI rules (Always On) — YOU HAVE NO DESIGN OPINIONS

**Every visible decision comes from the UI UX Pro Max skill. Not from your own taste, memory, or habits.**
"Every part of the UI" = layout, composition, colors, typography, spacing, radius, elevation, icons, illustrations, charts, motion, forms, navigation, empty/error/loading states, responsive behavior, component look.

Allowed sources of UI truth, in order:
1. `design-system/dormio/pages/<page>.md` (built from skill output)
2. `design-system/dormio/MASTER.md` (generated by the skill)
3. The bans in `docs/Design.md` §3 (restrictions only)

**If something is not specified there → run a gap query with the skill and record it. Never decide it yourself.**
**If the skill is missing, broken, or blocked → STOP and tell the owner. Never fall back to a self-made design.**

Procedure for ANY UI work (`/build-ui`, `docs/Design.md` §2):
1. `ls .agents/skills/ui-ux-pro-max/scripts/` and `python3 .agents/skills/ui-ux-pro-max/scripts/search.py --help`.
2. Ensure MASTER.md exists (else generate it per `docs/Design.md` §2.1).
3. Run the skill for this page/component: `--design-system --persist -p "Dormio" --page "<name>"`, plus `--domain ux`, `--domain style`, `--stack nextjs` (and `--stack shadcn`, `--domain icons`, `--domain chart` as needed).
4. Write `design-system/dormio/pages/<name>.md` with a `## UI UX Pro Max evidence` section: exact commands, chosen results, selection rationale. ≥ 3 recorded `search.py` commands.
5. Build with tokens only. First line of every `page.jsx`/`layout.jsx`: `// ui-spec: design-system/dormio/pages/<name>.md`. Register shared components in `design-system/dormio/COMPONENTS.md`.
6. Playwright screenshots at 360/768/1280 px → OPEN and review → fix → re-shoot (max 3 rounds). Fix needing a design choice = another skill query.
7. `bash scripts/check-ui-rules.sh` and `bash scripts/check-ui-provenance.sh` and axe must pass. Update `design-system/dormio/PAGES.md`.

Forbidden: choosing colors/fonts/sizes/spacing/icons/charts/animations/layouts by taste; hex colors or Tailwind arbitrary values for color/spacing/radius/font-size; default shadcn look; copying layouts from memory; gradients; black or dark theme; glassmorphism/neon/AI-purple; emoji icons; icon-in-circle feature rows; identical-box white pages; the same composition on consecutive pages; lorem ipsum; justifying a design as "modern/clean".

You may decide: code structure, state management, accessibility attributes, data fetching, naming. Nothing visual.
